# 축구 전술 보드

축구팀(11:11)의 포지션, 이동 동선, 전략을 정리해 링크로 함께 보는 모바일 브라우저용 앱입니다.

- **보기는 누구나**: 링크만 있으면 전술 목록, 경기장, 재생, 메모, 라인업, 선수단을 볼 수 있습니다. 열어 둔 화면은 5초마다 확인해서 바뀐 내용을 반영합니다.
- **전략 제시자 계정**: 오른쪽 위 “🔒 보기” → 이름과 개인 비밀번호. 처음 쓰는 이름이면 팀 편집 비밀번호(`EDIT_PASSWORD`)를 한 번 더 넣어 등록합니다. 다음부터는 이름과 개인 비밀번호만 넣습니다. 비밀번호는 해시로만 저장합니다. 같은 IP에서 5번 틀리면 10분 동안 막힙니다.
- **전술은 작성자만 수정**: 전술을 만든 사람(과 `ADMIN_NAMES`의 관리자)만 고치거나 지울 수 있습니다. 다른 사람은 “복사해서 내 전술로”를 눌러 복사본을 고칩니다. 선수단(명단)은 로그인한 전략 제시자 누구나 고칠 수 있습니다.

## 기능

- **선수단**: 등번호, 이름, 주 포지션 (최대 40명). “한꺼번에 입력”에 `10 홍길동 ST`처럼 한 줄에 한 명씩 붙여 넣으면 명단이 한 번에 등록됩니다.
- **포지션 기준 자동 배정**: 새 전술을 만들면 선수단의 주 포지션에 맞는 자리에 등번호 순으로 배정합니다(같은 포지션 자리가 여럿이면 앞 자리부터). 같은 포지션이 모자라면 비슷한 포지션으로 채웁니다(`app.js`의 `POS_GROUP`). 라인업에서 이름 옆의 같은 포지션 후보 버튼을 누르면 바로 바뀌고(다른 자리 선수면 맞바꿈), “포지션대로 다시 배정” 버튼과 포메이션 변경 때도 같은 규칙으로 다시 배정합니다. 선수단 탭에 포지션별 인원이 보입니다.
- **선수 배정**: 전술 화면 경기장 위의 명단 이름표를 끌어서 우리 팀 동그라미에 놓습니다(이름표를 누른 뒤 동그라미를 눌러도 됨). 이미 다른 자리에 있던 선수면 두 자리를 맞바꿉니다. 아직 자리가 없는 선수가 앞에 보입니다.
- **동그라미 이름**: 동그라미 안에는 포지션(ST 등)이, 이름을 정하면 아래에 “번호 이름” 이름표가 붙습니다. 편집 모드에서 동그라미를 누르면 명단에서 고르거나 명단에 없는 선수 이름·번호를 직접 적고, 포지션·역할 메모도 바꿀 수 있습니다. 상대 팀 동그라미도 이름·번호를 적을 수 있습니다. 보기 모드에서 누르면 이름과 역할이 잠깐 보입니다.
- **코치 전술**: “+ 새 전술” 맨 위 📋 “코치 전술: 박스 미드 → 측면 공략”(4-4-2 vs 4-2-3-1). 톱 둘 + 중미 둘의 박스로 가운데 숫자 싸움, 측면 미드가 올라가 생긴 바깥 공간으로 톱이 받아 측면 미드에게 연결, 옵션 ① 1:1 ② 기다렸다가 전방·중앙 패스 ③ 안쪽 + 윙백 오버래핑. 코치 아이디어를 AI가 장면으로 옮긴 것이라 📋 코치 아이디어 배지(`origin: 'coach'`)가 붙습니다. 템플릿의 `snapshot`/`restore`로 옵션 장면이 같은 장면 끝에서 다시 시작합니다.
- **추천 전술**: “+ 새 전술”에서 측면 오버래핑 크로스, 원투 패스 중앙 돌파, 빠른 역습(롱볼), 전방 압박, 코너킥 공격, 수비 블록(측면으로 몰아 빼앗기) 중 고르면 장면·동선·메모·역할이 채워진 채로 만들어집니다(`public/templates.js`). 선수 배정은 같은 포메이션의 최근 전술에서 이어받고, 없으면 주 포지션이 같은 자리에만 넣습니다.
- **✨ 다음 장면 추천** (규칙 기반, `public/suggest.js`): 편집 화면 장면 줄의 “✨ 추천”을 누르면 지금 장면이 끝난 위치(동선 끝)에서 공 가진 쪽, 공이 있는 구역(측면/중앙, 상대 진영/미드필드/우리 진영), 근처 선수를 보고 2~4개를 추천합니다. 카드를 누르면 미리보기, “✓ 적용”이면 다음 장면으로 추가합니다(지금 장면에 동선이 없으면 지금 장면에 넣음).
  - 우리 공: 측면 오버래핑, 크로스 & 박스 침투, 측면 돌파, 원투 패스, 뒷공간 스루패스, 롱볼 역습, 반대편 전환, 슈팅
  - 상대 공: 2명 압박, 전방 압박, 공 쪽으로 슬라이드, 라인 내리고 좁히기
  - 코너 근처 공: 코너킥 공격 / 코너킥 수비(지역), 주인 없는 공: 공 먼저 잡기
  - AI가 아니라 정해 둔 패턴을 지금 위치에 맞춰 그리는 것이라 출발점으로 쓰고 고쳐서 씁니다. 공 가진 선수는 공에서 3.5m 안의 가장 가까운 선수로 봅니다.
- **전술**: 제목, 작성자, 전체 메모, 우리/상대 포메이션(4-4-2, 4-3-3, 4-2-3-1, 4-1-4-1, 3-5-2, 3-4-3, 5-3-2), 자리별 선수 배정과 역할 메모
- **경기장**: 우리 팀(파랑, 아래에서 위로 공격) 11명, 상대 팀(빨강) 11명, 공. 손가락으로 끌어서 옮깁니다.
- **동선 그리기 (👆 동선 모드, 기본) — 누르기 두 번**: 선수를 누르면 선택(노란 테두리)되고 경기장 위 “할 일” 줄에 버튼이 뜹니다. 공 없는 선수는 🏃 달리기, 공 가진 선수(공 2.5m 안)는 ⚽ 패스 / 🥅 슛 / 🏃 드리블(이미 패스·슛이 있으면 🏃 달리기도). 달리기·드리블은 갈 곳을, 패스는 받을 선수(같은 팀에 점선 테두리)나 보낼 곳을 누르면 직선 동선이 생기고, 슛은 버튼만 누르면 공에서 먼 쪽 골포스트 안쪽으로 갑니다. ✏️ 이름·역할 창, 🧽 그 선수 선 지우기, ✕ 선택 해제.
- **끌어서 그리기 (같은 동선 모드)**: 끌기만 하면 종류는 알아서 정해집니다.
  - 선수를 끌면 달리기(흰 실선), 공을 가진 선수를 끌면 드리블(주황 점선, 공과 함께)
  - 공을 끌어 같은 팀 선수 근처(5m)에 놓으면 그 선수의 도착 지점(달리기 선이 있으면 그 끝)으로 붙는 패스(노란 점선). 아무도 없으면 빈 공간으로 패스
  - 공을 골문 앞에 놓으면 슛(굵은 분홍 실선)
  - 같은 선수(또는 공)를 다시 끌면 그 동선이 바뀌고, 받는 선수의 동선을 바꾸면 패스 끝도 따라갑니다. 이미 패스·슛 선이 있는 장면에서는 공 가진 선수를 끌어도 달리기
  - ✋ 배치 모드는 동선 없이 위치만 옮깁니다(시작 배치용). 공은 선수에게서 2.5m 안이면 그 선수가 가진 것으로 보고 발밑에 그립니다.
- **장면**: “+ 장면”은 지금 장면의 동선 끝 위치로 선수와 공을 옮긴 다음 장면을 만듭니다. 장면마다 이름과 설명을 적을 수 있습니다.
- **상대 자동 반응** (“+ 장면” 때, 편집 화면 체크로 끄고 켬, `Suggest.reactAway`): 직접 동선을 준 상대는 그대로 두고, 우리 공이면 가장 가까운 상대가 공을 압박하고 앞으로 5m 이상 뛰어 들어가는 우리 선수에게 가까운 상대(18m 안)가 따라붙고 나머지는 대형째 공 쪽으로 이동합니다. 상대 공이면 공 쪽으로 조금 전진, 주인 없는 공이면 가장 가까운 상대가 공으로 갑니다. 한 장면에 최대 12m(대형 이동 8m)까지만 움직입니다.
- **경기장 확대**: 경기장 오른쪽 아래 ＋/－/⤢ 버튼(최대 3배), 편집 중에는 두 손가락으로 벌리고 오므리고 끌어서 확대·이동.
- **작성자 / AI테스트 표기**: 목록과 전술 화면에 ✍ 작성자 이름을 보여 줍니다. 추천 전술로 만든 전술(`origin: 'ai'`)에는 🤖 AI테스트 배지, “✨ 추천”으로 넣은 장면 설명 앞에는 “[AI테스트 추천]”이 붙습니다.
- **재생**: 장면 순서대로 선수와 공이 동선을 따라 움직입니다(0.5x/1x/2x). 장면이 하나여도 동선이 있으면 재생됩니다.
- 편집 내용은 1초쯤 뒤에 자동 저장됩니다. 두 사람이 같은 전술을 동시에 고치면 나중에 저장한 쪽에 안내가 뜨고 최신 내용을 다시 불러옵니다.

## 매뉴얼과 버전

- 화면 상단 “📖 매뉴얼” 버튼: 새 소식(버전별 변경 내역)과 사용법. 내용은 `public/manual.js`(`VERSION`, `UPDATES`, `GUIDE`)에 있습니다.
- 이 기기에서 마지막으로 매뉴얼을 본 버전(localStorage `soccer.manualSeen`)보다 `VERSION`이 새로우면 버튼에 빨간 점이 뜨고, 매뉴얼을 열면 사라집니다. 아직 못 본 업데이트에는 NEW 표시가 붙습니다.
- 기능을 바꿀 때마다 `VERSION`을 올리고 `UPDATES` 맨 앞에 변경 내용을 추가하고, 사용법이 바뀌면 `GUIDE`와 이 README도 같이 고칩니다.

## 실행

```bash
npm install
npm start      # http://localhost:3000
npm test
```

설정은 `.env` 파일로 합니다(`.env.example` 참고, `.env`는 커밋하지 않음).

| 변수 | 설명 |
|---|---|
| `EDIT_PASSWORD` | 팀 편집 비밀번호. 전략 제시자가 처음 계정을 등록할 때만 씁니다. 없으면 기본값 `soccer`이므로 배포할 때 꼭 정하세요. |
| `ADMIN_NAMES` | 모든 전술을 고칠 수 있는 관리자 이름(쉼표로 구분, 예: `감독,코치`). 그 이름의 계정으로 로그인해야 합니다. |
| `TEAM_NAME` | 처음 팀 이름(앱의 선수단 탭에서 바꿀 수 있음) |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | 있으면 파일 대신 Upstash Redis에 저장 |
| `REDIS_KEY` | Redis 키 이름, 기본 `soccer:state` (Eatzy와 같은 DB를 써도 섞이지 않음) |
| `DATA_DIR` | Redis가 없을 때 `state.json`을 둘 폴더, 기본 `soccer/data` |

## Render에 올리기 (Eatzy와 별도 주소)

Render 대시보드 → **New → Web Service** → 이 저장소 선택 후:

- **Root Directory**: `soccer`
- **Build Command**: `npm ci --omit=dev`
- **Start Command**: `node server.js`
- **Instance Type**: Free
- **Environment**: `EDIT_PASSWORD`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`(Eatzy 서비스와 같은 값을 써도 됨), `REDIS_KEY=soccer:state`

주소는 서비스 이름에 따라 `서비스이름.onrender.com` 형태로 정해집니다. 무료 서비스는 15분 동안 접속이 없으면 잠들고, 다음 첫 접속 때 깨어나는 데 시간이 걸릴 수 있습니다. 데이터는 Upstash에 있어 유지됩니다.

## 구조

- `server.js`: 설정 읽기, 저장소 준비, 서버 시작
- `src/app.js`: API (`GET /api/state`, `GET /api/version`, `POST /api/login`, `POST /api/logout`, `PUT /api/team`, `POST/PUT/DELETE /api/strategies`). 로그인하면 세션 토큰을 주고 화면은 `x-session` 헤더로 보냅니다(저장 문서의 `sessions`에는 토큰 해시만). 계정은 `users`(id는 이름 소문자, scrypt 해시), 전술 주인은 `ownerId`
- `src/sanitize.js`: 화면에서 보낸 전술·선수단을 허용된 모양과 크기로 정리
- `src/store.js`: 문서 전체를 메모리에 두고 파일 또는 Upstash Redis에 통째로 저장 (단일 서버 전제)
- `public/formations.js`: 포메이션 프리셋 (서버와 화면 공용). 좌표는 미터 단위 68×105
- `public/templates.js`: 추천 전술 (장면별 시작 위치와 동선, 다음 장면은 동선 끝에서 시작)
- `public/suggest.js`: 상황별 다음 장면 추천 규칙 (`Suggest.suggest(위치, 포지션 이름)` → 상황 설명과 추천 동선)
- `public/app.js`: 화면 전체 (해시 주소 `#/`, `#/roster`, `#/s/전술id/장면번호`)
