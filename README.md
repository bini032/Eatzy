# Eatzy 🍱 점심 투표 · by SBComms

링크 하나를 팀원들과 공유해서 점심 가게 후보에 다같이 투표하는 웹앱입니다. Eatzy는 SBComms의 솔루션입니다. 투표하는 사람은 링크를 열고 이름만 입력하면 되고, 회원가입이나 설치가 필요 없습니다.

- **계정(이름 = ID)**: 처음 접속하면 이름을 입력합니다(비밀번호 없음). 이름은 서버 DB에 계정으로 저장되고, 같은 이름(대소문자·공백 무관)이면 같은 계정입니다. 투표와 메뉴 선택은 계정 기준이라 다른 기기에서 같은 이름으로 들어오면 내 표와 메뉴가 그대로 이어집니다. 브라우저는 마지막으로 쓴 계정을 기억해 다음부터 자동으로 들어가고, 상단의 👤 버튼으로 다른 계정으로 바꿀 수 있습니다.
- **그룹**: 이름 등록 창의 "👑 관리자로 시작하기"를 누르고 그룹 이름을 입력하면 새 점심 그룹이 만들어지고, 만든 사람이 그 그룹의 관리자가 됩니다. 그룹 주소는 `/g/그룹id` 형태이며(예: `https://…onrender.com/g/ab12cd34`), 상단의 "그룹 링크 복사"로 공유합니다. 그룹마다 투표, 가게 목록, 메뉴, 통계가 따로 저장되고 그룹 이름이 상단에 표시됩니다. 새 그룹은 기본 가게 목록(`restaurants.json`)으로 시작합니다. 그룹 관리자 권한은 그룹을 만든 브라우저에 저장되므로, 다른 기기에서는 관리자 권한이 없습니다. 기본 주소(`/`)는 기본 그룹입니다.
- **관리자 SB**: 이름을 `SB`(대소문자 무관)로 등록하려면 관리자 비밀번호(`ADMIN_KEY`, 기본 `hs`)를 입력해야 합니다. 등록되면 그 브라우저에서는 완료, 메뉴 편집, 가게 관리를 다시 입력 없이 쓸 수 있고, 다른 사람에게는 관리자 버튼이 보이지 않습니다. SB는 모든 그룹에서 관리자입니다.
- **가게 정보 미리보기**: 가게 이름(ⓘ)에 마우스를 올리면 주소, 전화, 메모, 메뉴와 가격, 지도 링크가 말풍선으로 보이고, 휴대폰에서는 이름을 누르면 아래에서 올라오는 창으로 보입니다.
- **화면**: 기본은 흰색(라이트)이고 🌙 버튼으로 다크 모드를 켤 수 있습니다. 언어는 한국어, English, 日本語, 中文 중에서 고를 수 있습니다(가게 이름·메뉴 같은 데이터는 원문 그대로).

## 기능

- **후보 직접 고르기**: "✋ 후보 직접 고르기"에서 가게 목록을 검색해 고르거나 목록에 없는 가게를 이름과 카테고리로 입력하면, 고른 가게들로 투표가 시작됩니다(최대 12곳). 직접 입력한 가게는 목록에 저장되어 다음에도 검색됩니다.
- **맛집 찾기**: 한식, 중식, 양식, 분식 카테고리별로 한 곳씩 후보를 뽑습니다.
  - 이전에 나왔던 가게는 피해서 매번 다른 곳을 뽑습니다. 카테고리의 가게를 한 바퀴 다 돌면 기록을 비우고 다시 시작합니다.
  - 직전에 최종 결정된 가게는 다음 투표 때 같은 카테고리 자리에 다시 나옵니다("지난 투표 1위" 표시).
- **투표**: 브라우저당 1표이며 바꾸거나 취소할 수 있습니다. 득표 현황은 3초마다 자동으로 갱신됩니다.
- **동점 랜덤 뽑기**: 1위가 2곳 이상이면 🎲 버튼이 나타납니다. 서버에서 한 번만 뽑아 모두에게 같은 결과를 보여 줍니다.
- **메뉴 선택**: 가게 카드에 등록된 메뉴가 모두 표시되고, 메뉴를 누르면 그 가게에 투표하면서 메뉴가 선택됩니다. 메뉴는 여러 개 고를 수 있고 다시 누르면 취소됩니다(가게 표는 1인 1표). 메뉴 없이 가게만 투표해도 됩니다.
  - 메뉴 이름에 가격이 있으면("짜장면 7,000원") 내가 고른 메뉴의 합계가 표시되고, 결정되면 결과 화면에 전체 예상 총액이 나옵니다. 가격이 없거나 범위로 적힌 메뉴는 합계에서 빠집니다.
  - 메뉴는 가게 목록 파일의 `menus`에서 가져옵니다.
  - 메뉴가 없거나 원하는 메뉴가 없으면, 누구나 카드의 "메뉴 직접 추가" 칸에 입력해 추가할 수 있습니다. 추가하면 그 메뉴로 바로 투표되고, 다른 사람도 고를 수 있습니다.
  - 메뉴 수정과 삭제는 관리자가 "메뉴 편집 (관리자)"에서 관리자 키를 넣고 합니다.
  - 추가하거나 편집한 메뉴는 저장되어, 다음에 같은 가게가 나와도 그대로 나옵니다.
  - 결정되면 결과 화면의 "🧭 찾아가기 (네이버 지도)" 버튼으로 바로 길찾기를 할 수 있습니다.
  - 결과 화면에 메뉴별 선택 인원("김치찌개 3명 · 제육볶음 2명")이 표시됩니다.
- **완료 (관리자)**: 관리자 키를 입력해야 확정됩니다(기본값 `hs`, 환경변수 `ADMIN_KEY`로 변경 가능). 키는 서버에서만 검증합니다. 확정되면 모든 사용자 화면에 결정된 가게가 표시됩니다.
- **결정 후 메뉴 고르기**: 결과 화면에서 누구나 결정된 가게의 메뉴를 고르고 바꿀 수 있습니다. 다른 가게에 투표했거나 투표하지 않은 사람도 됩니다. 주문 현황에 이름별 메뉴와 합계, 전체 예상 총액이 표시됩니다.
- **완료 후**: 누군가 투표, 메뉴 선택 같은 버튼을 누르면 "투표가 완료되었습니다! 담당자에게 직접 문의해주세요." 안내 창이 뜹니다. 그날 완료된 결과를 새 투표로 넘기려면 관리자 키가 필요하고, 다음 날부터는 누구나 새 투표를 시작할 수 있습니다(한국 시간 기준).
- 투표가 진행 중인데(1표 이상) 후보를 다시 뽑으려면 관리자 키가 필요합니다.
- **기준 위치**: 📍 내 현재 위치(HTTPS 또는 localhost에서만 동작), 🔎 장소 검색(카카오 키가 있을 때만), 기본 위치. 반경은 300m부터 2km까지 고를 수 있습니다.
  - 현재 위치의 건물 이름과 주소는 카카오 키가 있으면 카카오, 없으면 OpenStreetMap(Nominatim)에서 가져옵니다. OpenStreetMap에 건물 이름이 없는 곳은 동네 이름이나 주소만 나올 수 있습니다.
- **통계**: 이름별 "선택 적중 랭킹"(내가 투표한 가게가 최종 결정된 비율, 재미용)과 함께 월별(한국 시간) 점심 결정 횟수, 총 투표, 평균 참여 인원, 최다 결정 가게와 함께 가게 랭킹, 인기 메뉴, 카테고리별 결정, 표를 많이 받은 후보를 보여 줍니다. "전체 기간"도 고를 수 있습니다. 결정 기록은 약 2년치(730회)까지 보관합니다.
- **가게 관리 (관리자)**: 화면 맨 아래에서 관리자 키를 넣고 저장된 가게 목록을 보고, 추가하거나 삭제하고, JSON을 붙여넣어 한꺼번에 올릴 수 있습니다.

## 가게 후보를 가져오는 방식

앱은 아래 순서로 후보 출처를 정합니다.

1. **저장된 가게 목록(DB)**: PC의 Claude Code에서 `npm run upload-places`로 올리거나, 화면의 "가게 관리"에서 추가한 목록입니다. Upstash를 쓰면 서버가 재시작돼도 유지됩니다.
2. **가게 목록 파일 `restaurants.json`**: 저장된 목록이 비어 있을 때 사용합니다.
3. **카카오맵 실시간 검색**: 위 두 가지가 모두 비어 있고 `KAKAO_REST_API_KEY`가 있을 때 기준 위치 반경 안에서 검색합니다.

셋 다 없으면 앱은 가짜 가게를 만들어 내지 않고, 가게를 등록하라는 안내를 표시합니다.

### PC의 Claude Code로 목록 만들어 올리기

웹 페이지가 PC의 CLI를 직접 실행할 수는 없으므로, CLI가 만든 목록을 앱으로 올리는 방식입니다.

1. PC의 프로젝트 폴더에 `.env`를 만들고 아래 두 줄을 넣습니다.
   ```
   EATZY_URL=https://eatzy-xxxx.onrender.com
   ADMIN_KEY=hs
   ```
2. Claude Code에게 가게 후보를 찾아 달라고 하고, 고른 가게를 `restaurants.json`에 저장합니다(`CLAUDE.md`에 규칙이 있습니다).
3. 업로드합니다.
   ```bash
   npm run upload-places              # 기존 목록에 병합 (같은 이름+주소면 덮어씀)
   npm run upload-places -- --replace # 기존 목록을 지우고 교체
   ```
   특정 그룹에 올리려면 `.env`에 `EATZY_GROUP=그룹id`를 추가합니다.
4. 팀원들이 "맛집 찾기"를 누르면 올린 목록에서 후보가 뽑힙니다.

### 가게 목록 파일 형식

```json
[
  {
    "name": "가게 이름",
    "category": "한식",
    "address": "도로명 주소",
    "phone": "02-000-0000",
    "url": "지도 링크",
    "x": 126.0,
    "y": 37.0,
    "memo": "점심 특선 있음",
    "menus": ["김치찌개", "제육볶음"],
    "naverUrl": "네이버 지도 링크"
  }
]
```

- 필수 항목은 `name`, `category`(`한식`/`중식`/`양식`/`분식` 중 하나)입니다. 나머지는 선택입니다.
- `naverUrl`에 네이버 지도 장소 링크(예: `https://map.naver.com/p/entry/place/1234567`)를 넣으면 "네이버 지도"·"찾아가기"가 그 장소로 열리고, "메뉴 보기 (네이버)"가 네이버 플레이스 메뉴 탭으로 열립니다. 관리자 화면의 가게 목록에서 "네이버 링크" 버튼으로도 넣을 수 있습니다.
- `naverUrl`이 없으면 네이버 지도는 가게 이름으로 검색하고, `url`(출처 링크)이 "가게 정보"로 표시됩니다.
- `menus`는 메뉴 이름 배열입니다. 비워 두면 관리자가 앱에서 직접 입력할 수 있습니다.
- `x`(경도), `y`(위도)를 넣은 가게만 거리가 표시되고 반경으로 걸러집니다. 좌표가 없는 가게는 항상 후보에 들어갑니다.
- 파일을 고치면 서버를 다시 켜지 않아도 다음 "맛집 찾기"부터 반영됩니다.
- `npm run check-places`로 형식 오류와 카테고리별 가게 수를 확인할 수 있습니다. 형식이 틀린 항목은 무시됩니다.
- 카카오맵 등 외부 서비스의 검색 결과를 옮겨 적을 때는 해당 서비스의 이용 정책(저장 허용 범위)을 먼저 확인하세요.

### 카카오 REST API 키 (선택)

1. https://developers.kakao.com 에서 애플리케이션을 만듭니다.
2. **앱 키 > REST API 키**를 복사합니다.
3. 앱 관리 페이지에서 카카오맵(로컬 API) 사용 설정을 켭니다. 호출이 403으로 거부되면 이 설정을 확인하세요.

무료 제공량과 요금, 이용 정책은 바뀔 수 있으니 카카오디벨로퍼스 문서에서 확인하세요.

## 실행

Node.js 20.12 이상이 필요합니다.

```bash
npm install
npm start          # http://localhost:3000
npm test           # 자동 테스트 (외부 API는 가짜 응답으로 대체)
```

설정은 프로젝트 폴더에 `.env` 파일을 만들어 넣으면 됩니다(`.env.example` 참고). Windows, macOS 모두 같은 방식입니다.

## 다른 사람들에게 링크로 공유하기

앱이 켜져 있는 동안에만 링크가 동작합니다. 두 가지 방법이 있습니다.

### A. 내 PC에서 실행하고 임시 링크 만들기 (가입 불필요)

1. `npm start`로 앱을 켭니다.
2. 다른 터미널에서 [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)를 설치한 뒤 실행합니다.
   ```bash
   cloudflared tunnel --url http://localhost:3000
   ```
3. 출력되는 `https://….trycloudflare.com` 주소를 공유합니다.

- PC와 두 터미널이 켜져 있을 때만 접속됩니다. 실행할 때마다 주소가 바뀝니다.
- 회사 PC라면 외부 터널 사용이 보안 정책상 허용되는지 먼저 확인하세요.

### B. 클라우드에 올려서 고정 링크 쓰기 (무료 조합)

**Render 무료 웹 서비스 + Upstash Redis 무료 DB** 조합이면 유료 디스크 없이 기록을 유지할 수 있습니다. 무료 웹 서비스는 파일이 보존되지 않으므로, 투표 데이터를 Upstash Redis에 저장합니다.

1. **Upstash**: https://upstash.com 에 가입하고 Redis 데이터베이스를 만든 뒤, REST API의 `UPSTASH_REDIS_REST_URL`과 `UPSTASH_REDIS_REST_TOKEN` 값을 복사합니다.
2. **Render**: GitHub 계정으로 로그인한 뒤 New → Blueprint로 이 저장소를 연결하면 `render.yaml`(무료 플랜)이 적용됩니다.
3. 환경변수에 `ADMIN_KEY`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`을 입력합니다. 카카오 검색을 쓸 때만 `KAKAO_REST_API_KEY`를 넣습니다.

- Render 무료 서비스는 15분 동안 접속이 없으면 잠들고, 다음 첫 접속 때 깨어나느라 1분 정도 걸릴 수 있습니다. 데이터는 Upstash에 있으므로 잠들었다 깨어나도 유지됩니다.
- 앱은 상태가 바뀔 때만(투표, 완료 등) Upstash에 저장하고, 화면 자동 갱신은 Upstash를 호출하지 않습니다. 점심 투표 정도의 사용량이면 무료 한도(월 명령 수)를 넘기기 어렵습니다.
- 두 서비스의 무료 조건은 바뀔 수 있으니 가입할 때 각 요금 페이지에서 확인하세요.
- Upstash에 연결하지 못하면 기존 데이터를 빈 상태로 덮어쓰지 않도록 서버가 시작하지 않습니다. 로그에 원인이 표시됩니다.
- **Docker 기반 서비스** (Railway, Fly.io, Cloud Run, 사내 서버 등): 포함된 `Dockerfile`을 사용하고, `/data` 경로에 볼륨을 마운트합니다.
  ```bash
  docker build -t eatzy .
  docker run -p 3000:3000 -e ADMIN_KEY=... -v eatzy-data:/data eatzy
  ```

투표 데이터는 Upstash 설정이 없으면 `DATA_DIR`(기본 `./data`)의 JSON 파일 하나에 저장됩니다. 어느 쪽이든 **서버는 1대로 운영**해야 합니다. 파일 저장을 쓸 때는 `DATA_DIR`을 영구 디스크에 두어야 재시작 후에도 기록이 남습니다. 기록이 사라지면 진행 중인 투표, "지난 1위 다시 노출", "중복 없이 뽑기"가 처음부터 다시 시작됩니다. 가게 목록 `restaurants.json`은 저장소에 함께 들어 있으므로 영향을 받지 않습니다.

## 환경변수

| 이름 | 설명 | 기본값 |
| --- | --- | --- |
| `ADMIN_KEY` | 완료/재추첨 관리자 키 | `hs` |
| `RESTAURANTS_FILE` | 가게 목록 파일 경로 | `./restaurants.json` |
| `KAKAO_REST_API_KEY` | 카카오 REST API 키 (목록이 비어 있을 때 실시간 검색에 사용) | 없음 |
| `DEFAULT_PLACE_QUERY` | 기본 위치 이름 (카카오 키가 있으면 이 이름으로 좌표를 검색) | `더존을지타워` |
| `DEFAULT_ORIGIN_X`, `DEFAULT_ORIGIN_Y` | 기본 위치 좌표를 직접 고정 (경도, 위도) | 없음 |
| `EATZY_URL` | `npm run upload-places`가 올릴 배포 주소 (PC에서만 사용) | 없음 |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | 설정하면 파일 대신 Upstash Redis에 저장 | 없음 |
| `REDIS_KEY` | Upstash에 저장할 키 이름 | `eatzy:state` |
| `DATA_DIR` | 투표 데이터(JSON) 저장 폴더 (Upstash 미사용 시) | `./data` |
| `PORT` | 포트 | `3000` |
